PRD — General Template (for Web Development & Vibe Coding)

⸻

1. 📌 Document Control
	•	Project Name: [Enter project/product name]
	•	Version: [v1.0 / Draft / etc.]
	•	Author / Owner: [Name, Role]
	•	Date Created: [DD/MM/YYYY]
	•	Last Updated: [DD/MM/YYYY]

⸻

2. 🎯 Purpose & Background
	•	Why are we building this?
Short context: business opportunity, user pain point, or strategic need.
	•	Problem Statement:
Clear description of the user problem or gap in the market.
	•	Success Criteria (How we know it’s working):
	•	Metric 1 (e.g., 1,000 signups in 30 days)
	•	Metric 2 (e.g., reduce checkout time by 20%)

⸻

3. 👥 Target Users & Personas
	•	Primary User: [Who is the main target? E.g., “Small business owner managing online orders”]
	•	Secondary Users: [Who else might use it indirectly?]
	•	Pain Points: [List of problems we’re solving for them]

⸻

4. 🧭 Goals & Non-Goals
	•	Goals (Scope IN):
	•	Feature/Capability A
	•	Feature/Capability B
	•	Business outcome we want
	•	Non-Goals (Scope OUT):
	•	What this release will not cover (to avoid scope creep).

⸻

5. ⚙️ Features & Requirements

For each feature, specify:

Feature Name: [Short label]
	•	Description: [What it does, why it matters]
	•	User Story: “As a [user], I want [capability], so that [benefit].”
	•	Acceptance Criteria:
	•	Condition 1
	•	Condition 2
	•	Priority: [P1 = Must-have, P2 = Should-have, P3 = Nice-to-have]

⸻

6. 📐 Functional Requirements
	•	UI/UX Requirements: Wireframes, layouts, or design references.
	•	System Requirements:
	•	Frontend: [React / Next.js / etc.]
	•	Backend: [Node.js / Django / etc.]
	•	Database: [MySQL / Postgres / etc.]
	•	Integrations: APIs, third-party services (e.g., Stripe, Auth0).

⸻

7. 🔒 Non-Functional Requirements (NFRs)
	•	Performance: e.g., < 2s page load.
	•	Security: OAuth 2.0, password encryption, GDPR compliance.
	•	Scalability: Handle X concurrent users.
	•	Accessibility: WCAG 2.1 compliance.

⸻

8. 📊 KPIs & Analytics
	•	What metrics we’ll track (conversion rate, DAU/MAU, churn, etc.).
	•	How we’ll measure them (Google Analytics, custom dashboard, etc.).

⸻

9. 🗺️ Milestones & Timeline
	•	MVP Release: [Date + what’s included]
	•	Beta Release: [Date + what’s included]
	•	Full Release: [Date + what’s included]

⸻

10. ⚠️ Risks & Assumptions
	•	Risks: Possible blockers (e.g., dependency on external API).
	•	Assumptions: What we’re assuming true (e.g., user adoption will start from existing client base).

⸻

11. ✅ Approval & Sign-off
	•	Stakeholders: Who must approve this document (e.g., PM, Tech Lead, Founder).
	•	Decision Log: Record of key product decisions.
